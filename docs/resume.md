# 可选续玩

## 玩家操作
标题的「继续此前保存」只在记录完整验证后可用，并显示关卡、步数和推数；不会自动进入旧局面。也可以直接去中庭选择新关。

正常游玩停手约1秒后，游戏核对完整历史，自动提交间隔至少5秒。成功恢复会保留角色、箱子、步数、推数与全部撤销历史；重置也仍可撤销。不恢复动画或尚未执行的方向缓冲。已胜利的局面由原有通关流程协调，不直接从续玩文件赋予解锁。

关闭窗口时保存已经提交的逻辑状态，最多等待约1.5秒。若超时或不能保存，会明确列出此前核对记录，说明它不是当前最新局面且不保证仍能恢复。可返回游戏或仍然退出；返回后先松开方向键再移动，不执行退出前旧缓冲。

## 安全与限制
- 永久进度仍是V2 `user://fourfold_progress.json`；续玩独立使用 `user://fourfold_resume/resume.json`，不迁移或降级永久进度。
- 磁盘续玩最多8192条完整历史、64KiB文件。超限拒绝保存，不截断运行中的undo，也不覆盖上次有效记录。撤销回范围内可重新尝试。
- 坏档、未来格式、不兼容规则、外部文件修改、未知lock/pending均保留原文件，本次续玩保存暂停。当前局面仍可正常游玩和无限撤销。
- 已知磁盘token变化立即禁用继续按钮；只保留明确标注「不能确认可恢复」的参考摘要。不会把内存中的旧candidate冒充磁盘最新存档。
- 如果退出超时取消了尚未完成的旧档核对，本次明确转为只读暂停，不能未经验证授权覆盖；返回游戏不再虚假承诺停手即自动保存。
- 不自动抢锁、删文件或恢复遗留事务，也不要求玩家手动清文件。本阶段没有遗留事务自愈工具。强杀可能留下保护锁，导致后续保存暂停；不保证恢复最后一个未提交动作。
- 校验与提示共用每帧约2ms软预算；退出校验最多使用8ms软切片。规则单步、JSON处理、数组析构和文件提交不可抢占，极端历史可能有几十毫秒尖峰；不是硬实时或零卡顿承诺。
- 保存采用临时文件读回检查、合作式目录锁、磁盘token与原子rename；没有先删除旧文件的回退。不等于硬断电fsync保证，也不是抵御恶意本机进程的认证机制。

## 实现与测试边界
`resume_codec.gd` 注入生产PuzzleRules，原型snapshot未复制。`resume_store.gd`仅调整必要preload路径；controller管理revision、校验及节流，main管理UI与退出。

云端故障后main/controller从本代理保留的代码调用重建，SHA256与故障前一致。原型和生产测试都必须在恢复环境重新执行，故障前未结束的204关回归不计通过。最新证据见 `docs/TEST_REPORT.md`；不将Linux结果称作macOS已验证。
