# V2 关卡求解、去重与捷径验证

## 验证范围

- `tests/solver_report.json` 保存全部参考解、每一步状态、最少推动/步数、机制使用与绕过检查。

## 精确求解算法

参考规则为 `tools/puzzle_solver.py` 的 `Level.step`。宏推动求解器在每个箱子布局下用实际规则 BFS 求玩家最短取位路径，再枚举合法推动，用 Dijkstra 比较 `(推动次数, 步数)`。保留推动后玩家的真实位置，绝不把方向根门中的不同位置粗暴合并成一个可达区域。

死格剪枝只使用放宽规则后的单箱可达性：忽略关闭桥和箭头、允许箱子停在任意滑道前缀、传送可以原地停或转移。放宽仅增加可能性；在这张图里仍无法抵达任何目标的格子才能被剪掉。达到预算记作 `budget_exhausted` 并拒绝候选，不写作无解。

原逐步 Dijkstra 保留为独立对照实现。宏求解器不统计所有等价行走串，不能据其搜索树声称“唯一解”。

## 去重与捷径门槛

- 全部 200 主线关卡按旋转 0/90/180/270 度与镜像的 8 种变换规范化，箭头方向和传送配对一起变换。
- 指纹不包含玩家起步位置，避免同一个箱子谜题只换起步格就计为新关。
- 同世界额外移除所有特殊地形，再对可走格、箱子和目标去重：200 个世界内骨架均独立。
- 保留所有规则，仅禁止使用该世界的核心机制重新求解：192 个主线关卡无解；8 个有替代路线，但至少多 3 次推动。没有同代价绕过的“装饰机关”被留在教学关。
- 四个奖励关逐项禁止其任一种机制都会无解。

## 真实规则契约

1. 网格 x 向右、y 向下，动作 U/D/L/R。箱子无身份，位置排序作为规范状态。
2. 桃风滑道：箱子沿推动方向滑过连续滑道，遇普通格停止；若下一格阻挡则停在最后合法滑道格。玩家不滑行。
3. 成对炉门：箱子最终落脚在入口时只传送一次；出口阻挡则整步无效；玩家不传送。
4. 方向根门：箭头约束玩家和箱子的进入方向，离开方向不限。
5. 压板桥：根据移动前箱子压板情况判断通行；完成后若桥关闭，不得有玩家或箱子留在桥格，否则整步拒绝。
6. 全部状态变化在一个离散动作内完成，没有隐藏时间推进或随机判定。
