# 持续开发路线

依据 2026-10-23 的用户授权：以 `beekim123/pushbox3d-dot` 为主仓库，持续开发推箱子相关内容；每个可检查阶段提交，保留历史；用户叫停前不以一次 ZIP 交付作为结束。可自主扩展四方向之外的内容，但不以堆数量代替体验。

## 当前阶段 A：V2 园景与 200 主线
- 蟠桃仙园替代宫殿，四界自然/建筑地貌重制。
- 四方各50关，40章旅程菜单，4关交汇奖励。
- 全部解答、对称去重、机制旁路、存档安全、真实运行时与实际截图验证。
- 分批迁入代码、生成脚本、运行资源、Blender源和测试证据；未齐备时明确WIP，不称完整发行版。

## 下一阶段 B：卡关支持与操作体验
- 可选渐进提示：从当前棋局求下一推，而不是只播放开局答案。
- 异步/逐帧预算，可取消；移动、撤销、重置与换关后废弃旧结果。
- 严格区分无解、已完成与预算耗尽，不能用“超时”误判死局。
- 默认给轻提示；玩家主动展开具体推法/到位路线，不自动代操作。
- 之后补充中途退出恢复棋局、输入与易读性细节，维持无限撤销。

## 后续阶段 C：美术与性能持续打磨
- 以实际游戏镜头而非单张Blender展示图检查。
- 保留原创形体细节，同时减少无效几何/绘制调用与遮挡。
- 增加画质/声音可调性及可访问性反馈，测试结果注明设备范围。
- 在已有章节中做真人反馈驱动的谜题精修，不盲目增加数量。

## 后续阶段 D：原创机制试验
在独立分支/目录验证一个新机制的小型章节，再决定是否进入主线。需要新的确定性规则、求解器、教学曲线与原创美术；不直接改坏原有204关，不把实验关混称已验收内容。

## 每阶段的提交要求
1. 列出具体变更和不变部分。
2. 执行相关可重复测试；图形改动有真实截图。
3. 记录缺陷与未验证范围，不把通过逻辑测试等同于审美认可。
4. 提交并读回仓库commit；不force推送，不覆盖别人的并发变更。
5. 确认备份与交付后进入下一项有明确价值的工作，而不是制造空提交。
