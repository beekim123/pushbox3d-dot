# 决策记录

- 本项目独立于清欢小星及其他仓库。新建 fourfold_atelier，不改旧工程，不继承旧项目像素风或无图片资产限制。本次明确要求 Blender 模型、GLB 与原创音频。
- 原创名称「四隅织途 / Loom of Four Horizons」，以线轴邮差修复四向织机为统一叙事。参考作品只提供可读性、世界结构和精致度启发，不复制关卡、角色、界面或音乐。
- 先完成联网研究再确定设计。参考图片不进入项目；截图仅来自我们自己制作的 Blender / Godot 内容。
- 采用 16 关紧凑流程。四世界各三关，四道双机制交汇。优先规则教学与真实求解验证，不用关卡数量充当质量。
- 四世界采用滑行、成对传送、单向根门、压力桥。均为离散可验证规则，与各自主题呼应；交汇关不引入第五种规则。
- 高差主要用于建筑和地基构图，解谜维持单层离散格点，以避免斜视视角下隐藏路径。重庆主题通过叠楼、桥、支撑与阶梯体现，不冒称立体重力谜题。
- Godot 4.7.2 精确版本用于导入和测试。Blender 4.3.2 为现有工具。Cycles 如不具备 OpenImageDenoise，关闭降噪并提高采样，而不是下载现成资产。
- 所有资源程序化原创生成，但最终模型、材质、角色动画都由 Blender 输出，保留生成脚本与 .blend。游戏移动插值属于逻辑呈现，不代替模型内动作。
- 音乐由数值合成创作，主题变奏统一四方；不采样已有作品。音频脚本与循环/峰值检查保留。
- 采用系统字体避免引入字体素材；跨平台字体回退需要实际检查，不能用 Linux 验证冒充 macOS 验证。

## 实机迭代
- 第一轮 Godot 天宫出现严重高光裁切，Blender 预览不能替代游戏渲染检查。改用线性映射和较低的主光/环境填充，保留地块固有色，并重新截图。
- 给外围建筑和生物补上 GLB 台阶/基座，避免像资产陈列一样悬浮；缩短 HUD，为场景腾出面积。
- 优化只对 Blender 导入的重复静态网格进行实例化批处理，不用运行时生成网格替代原创模型。角色、传送环与桥门保留 Blender 动画。
- 独立检查发现交汇末关可以绕过部分机关，重做两道交汇关，并以“保持规则、禁止使用某机制”的独立搜索验证：最终四道交汇关都必须使用各自两种机制。
- 传送不是沿两端直线穿墙移动，使用消失/再出现反馈；所有实体逻辑仍是离散、确定、可完整撤销。
- 全部界面字符在 Linux 的实际系统字体链上自检；macOS 未实际运行，不把云端通过写作全平台通过。
- 对 llvmpipe/lavapipe 软件渲染器自动使用 0.60 的 3D 分辨率比例、512 阴影图及关闭 MSAA；真实 GPU 默认不降级，F2 可切换。实际 CPU 软件渲染依然远低于 60 FPS，因此报告明确保留性能边界，不用截屏替代性能证明。
- Godot 的 `--quit-after` 会立即终止，无法等待音频混音线程回收。常规窗口关闭执行显式 stop/清空/等待收尾；纯 headless 默认不启动声音，以便 CI/命令行验证稳定退出。`--headless-audio` 可显式开启混音进行有序退出的音频集成验证。这不禁用正常游戏的声音，也不把无声测试冒充音频播放测试。

- 首个完整 ZIP 为 53 MB，聊天附件拒收。将自己合成的六首音乐、四条环境声编码为 Ogg Vorbis q6，八个短音效保留 WAV；保留所有 Blender 源文件和完整音频生成脚本。压缩只改变音频存储格式，不删关卡、美术、源文件或文档。


## 可选渐进提示整合（V2 之后）
- H 打开轻线索时只显示当前机制提醒，不立即求解；玩家主动按 J 或按钮才从当前棋局启动有界搜索。第二层只标出下一只箱子和一个推动方向，第三层才显示角色走到推位的短路线，永不自动移动、永不展示整关答案。
- 运行端只复制独立验收的 `hint_solver.gd`，不引入原型快照的重复规则类。默认累计节点上限8000，UI不开放高预算。达到上限与已证明无解分开说明，未算完不得宣称死局。
- 主场景持有同一个solver跨菜单/关卡使用。移动、撤销、重置、换关、帮助弹窗及关闭提示均使请求号失效并移除全部标记；即使提示关闭也逐帧用同一2ms软预算回收退休搜索，正常退出等回收完成。
- 标记属于2D界面：把真实箱子/站位投影成金圈、单箭头、薄荷色到位线，不新增运行时3D模型；原有Blender素材约束保持。左侧300逻辑像素小浮板不扩占底栏，H/J/Esc可完成全部提示操作。
- 2ms为软墙钟切片，不是硬实时承诺。默认上限内也可能因系统调度产生尖峰；完整3D窗口的软件渲染性能与求解器预算是两回事。

## 可选续玩与故障后恢复
- progress V2不变，新增独立sidecar；完整规则重放通过后才开放可选继续。标题不自动跳转，旧checkpoint不冒称最新。
- 成功移动/undo/reset/换关递增revision，取消一次旧编码；停手1秒、提交间隔5秒。读写codec独立，后台加载不会抢走当前界面。
- 退出有约1.5秒墙钟预算，失败显示可见确认而非消失前toast。返回保留当前完整undo，并要求先释放方向键。
- 8192条仅为磁盘完整历史上限；坏档/未来格式/外部token变化/未知lock或pending保守保护，不自动抢锁或删除。取消初始校验也必须明确暂停，不能静默停存。
- 外部token变化清除可恢复candidate，只留不能保证恢复的参考摘要；退出不承诺旧文件一定可恢复。
- 云端故障后的main/controller逐字恢复并与旧SHA一致，但旧未结束回归不算通过。所有生产集成、GUI和跨进程证据重新产生，先WIP远端备份，再验收合并。

## F1 情境帮助（最小教学补充）
- 仅在实际棋局模式的既有F1帮助中加入「本章练习」，读取当前关卡chapter_name与learning_goal；缺任一项、非字符串（包括null/数字/数组）或去空白后为空则省略，菜单/中庭/标题不借用残留level说明。
- 只为heaven_13与city_04显示已审的观察问题，不给坐标、参考最优步数或完整路线；confluence用温和的机制配合练习。stage_intent/design_facts不作为必经步骤，不新增运行时solver_report依赖。
- 不新增按钮或自动弹窗，不改H/J求解器、关卡、规则、存档。帮助关闭/替换时才清旧缓冲并记录旧按住的方向键；用_input释放事件解除独立guard，支持同一渲染帧内松开再按，不只依赖下一帧轮询。
- 不杀已提交的移动tween；R/Z仍有意关闭帮助并重置/撤销，胜利协调沿用既有流程。普通弹窗不套用此帮助guard，退出保存决策期间拒绝F1替换。

## 完成局面与完成面板协调
- 合法逻辑终点先于移动动画提交。撤销重置恢复胜局时必须核对实际完成登记；不能因为首个赢局动画曾被取消，就只画面板却仍锁下一关。
- 完成登记与面板呈现分离；solved/best真正改变才写永久进度。已经登记的胜局经撤销恢复、继续此前保存、退出取消或帮助关闭重画，不重复胜利声音/庆祝/永久写盘。尚未登记的合法完成仍登记一次；更优成绩仍正常更新。
- 帮助仅在其专用关闭入口检查当前真实胜局，恢复下一关/撤销/选关动作；R/Z、切关、退出仍走原通用关闭路径，不保留陈旧返回意图。纯呈现函数拒绝非棋局、非胜局、退出过程。
- 不改规则、关卡、无限撤销/重置记录、H/J或存档格式。普通完成面板的Esc仍允许收起（可从选关继续）；本轮不扩写全通中庭庆典的帮助返回行为。
